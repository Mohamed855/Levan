# جرد الإدارات القديمة قبل نقل لوحات التحكم

> هذا الجرد يصف العقد القائم في `old` فقط. لا يمثل قرارًا جديدًا في الأعمال. عند اعتماد أي تغيير، يوثق القرار هنا ثم تنقل الإدارة كاملة وفق [خطة النقل](dashboard-migration-plan.md) و[عقد DataTable ونقل قواعد الأعمال](architecture/datatable-contract.md). تحسين الـstructure أو الواجهة لا يبرر حذف workflow أو صلاحية أو فلتر أو حالة قائمة.

## قواعد قراءة الجرد

- **الفهرس** يوضح الإحصاءات والفلاتر والأعمدة التي يقدمها المصدر القديم.
- **النموذج** يسجل الحقول التي تقبلها الواجهة وطلبات التحقق الحالية.
- **الفجوة** تعني نقصًا أو اختلافًا قائمًا في النسخة القديمة، ويعالج في النقل وفق الـGolden pattern.
- كل الصفحات ذات `is_active` أو حالة قابلة للتبديل ستأخذ Toggle في الجدول الجديد. ألوان الحالة تأتي من تعريف الحالة في الخلفية؛ وما عداها يستخدم `bg-label-primary`.

## إدارة المنصة (Admin)

### لوحة الإدارة

- **البيانات:** مؤشرات المنصة والنشاط الأخير، مع مسار مستقل لنشاط المنصة.
- **النقل:** لوحة محتوى خاصة بـAdmin داخل `layouts.dashboard` المشترك، مع وحدات إحصاءات ورسوم تعتمد على خدمات خلفية صريحة.

### العملاء / الشركات

- **الفهرس:** الإحصاءات: الإجمالي، النشط، الموقوف، المعلق، وبدون اشتراك. الفلاتر: حالة آخر اشتراك، الباقة، المدينة، قرب الانتهاء، ومن/إلى تاريخ الإنشاء. الجدول: تحديد، الشركة، المسؤول، المدينة، الرقم الضريبي، السجل التجاري، معرّف المستأجر، الباقة، المستخدمون المستهلكون، البداية، النهاية، الأيام المتبقية، حالة الاشتراك، الإجراءات.
- **الإنشاء:** بيانات الشركة `company_name, commercial_number, tax_number, city_id, address`؛ الإعدادات `email_notifications_enabled, two_factor_enabled, external_integrations_enabled`؛ مسؤول المستأجر `name, phone, email, password, password_confirmation`؛ والاشتراك `plan_id, start_date, end_date, payment_type, payment_method, receipt_upload, trial_end_date, has_discount, discount_value, activate_immediately`.
- **التعديل الحالي:** بيانات الشركة والمسؤول الحالي وإعدادات التمكين فقط: `company_name, commercial_number, tax_number, city_id, address, primary_contact_name, primary_contact_email, primary_contact_phone` وإعدادات التمكين.
- **الفجوة:** الاشتراك ومسؤول المستأجر غير ظاهرين في edit. في النقل سيظهر النموذج نفسه كله؛ غير القابل للتعديل سيكون معروضًا ومعطّلًا، وUpdate Request لا يتحقق إلا من الحقول القابلة للتعديل. قواعد السجل والرقم الضريبي تعتمد النمط المعتمد في المشروع الجديد.

### الاشتراكات المركزية

- **الفهرس:** الإحصاءات: الإجمالي، النشط، المعلق، المنتهي، والقريب من الانتهاء. الفلاتر: الحالة، الباقة، مدينة الشركة، قرب الانتهاء. الجدول: تحديد، رقم الاشتراك، الشركة، الرقم الضريبي، المستأجر، الباقة، حدود الباقة، البداية، النهاية، الأيام المتبقية، الحالة، الإجراءات.
- **الإنشاء:** `company_id, plan_id, start_date, end_date, payment_type, payment_method, receipt_upload, has_discount, discount_value, trial_end_date, activate_immediately`، مع عرض حدود الباقة للقراءة.
- **العمليات:** تغيير الحالة، حذف، جلب مدة الباقة وتفاصيل الشركة.
- **الفجوة:** لا يوجد edit حاليًا؛ قرار الأعمال سيحدد هل هو إنشاء جديد فقط أم يحتاج تعديلًا كاملًا بالنموذج الموحد.

### متابعة الاشتراكات

- **الصفحات:** المعلقة، القريبة من الانتهاء، والمنتهية.
- **الجدول:** تحديد، الشركة، المدينة، الرقم الضريبي، المستأجر، الباقة، البداية، النهاية/نهاية الفترة، الأيام المتبقية، الحالة، السعر، الإجراءات.
- **العمليات:** قبول أو رفض فردي وجماعي. طلب الرفض يحمل سببًا.
- **الفجوة:** صفحة تشغيلية بلا نموذج CRUD؛ تنقل كإدارة إجراءات مع إحصاءات وفلاتر يحددها الخلفية.

### الباقات

- **الفهرس:** الإحصاءات: الإجمالي، النشط، غير النشط، المتاح، والمستقبلي. الفلاتر: التفعيل، نوع الباقة، دورة الفوترة، وضع الحدود، الإتاحة، والخصم. الجدول: تحديد، اللون، الاسم، الكود، الأكثر طلبًا، النوع، دورة الفوترة، السعر، الخصم، السعر بعد الخصم، سعر التجديد السنوي، وضع الحدود، حدود المستخدمين/العقارات/التخزين/المزادات، تاريخ الإتاحة، إدارة الدومينات، التفعيل، الإجراءات.
- **الإنشاء والتعديل:** `name, code, plan_type, color, description, price, discount_percentage, yearly_renewal_price, subscription_billing_cycle, available_from, admin_notes, is_active, domain_management_enabled, limits_mode, features[]`، وحدود الباقة المقيدة `included_users, extra_user_license_price, properties_limit, storage_quota_gb, active_auctions_limit`.
- **العمليات:** ترتيب الباقات وتغيير التفعيل وعرض التفاصيل.

### الكوبونات

- **الفهرس:** الإحصاءات: الإجمالي، النشط، غير النشط، والمنتهي. الفلاتر: التفعيل ونوع الخصم. الجدول: تحديد، الكود، نوع الخصم، التفعيل، الانتهاء، الإجراءات.
- **الإنشاء والتعديل:** `name, code, discount_type, discount_value, max_discount, expiry_date, usage_limit, is_active, admin_user_id`.
- **العمليات:** تغيير التفعيل، تفاصيل الاستخدام، والأرشفة.

### مستخدمو الإدارة والأدوار

- **المستخدمون — الفهرس:** الإحصاءات: الإجمالي، النشط، غير النشط، المؤرشف، ومديرو النظام. الفلاتر: الحالة والدور. الجدول: تحديد، الصورة، بيانات المستخدم، الأدوار، الحالة، آخر دخول، الإجراءات.
- **المستخدمون — النموذج:** الاسم، البريد، الجوال، كلمة المرور وتأكيدها، الصورة، والحالة/الدور بحسب النموذج القديم؛ مع تحققات تفرد للاسم والبريد والجوال. العمليات: تعديل، Toggle، حذف جماعي، ملف شخصي، وإسناد الأدوار.
- **الأدوار — الفهرس:** تحديد، الاسم، عدد المستخدمين، عدد الصلاحيات، تاريخ الإنشاء، الإجراءات، مع إحصاءات خدمة الأدوار.
- **الأدوار — النموذج:** اسم الدور ومصفوفة الصلاحيات المصنفة حسب الأقسام.

### قوالب المزادات

- **الفهرس:** تحديد، الاسم، النوع، الملف، تاريخ الإنشاء، التفعيل، الإجراءات؛ وفلاتر النوع والحالة.
- **الإنشاء والتعديل:** `name, type, description, file, field_definitions, is_active`. الملف PDF أو صورة، وتعريف الحقول مصفوفة.
- **العمليات:** Toggle وعرض الحقول.

### الفواتير والمدفوعات

- **الفواتير — الفهرس:** تحديد، المستأجر، النوع، رقم الفاتورة، المبلغ، مبلغ التسوية، طريقة الدفع، الحالة، تاريخ الإنشاء، الاستحقاق، الإجراءات. الفلاتر: نوع العملية، الحالة، وطريقة الدفع.
- **الصفحة والتشغيل:** عرض وطباعة، توثيق التحويل، رفضه بسبب، وإعادة تفعيل الفاتورة.
- **معاملات الدفع:** صفحة فهرس منفصلة قديمة؛ تؤجل للجرد التفصيلي عند نقل مجال المدفوعات لأنها لا تحمل Controller مستقلًا في المصدر الحالي.

### الدعم والطلبات العامة

- **تذاكر الدعم:** الفهرس: تحديد، رقم التذكرة، المستأجر، العميل، القسم، الحالة، تاريخ الإنشاء، الإجراءات. العمليات: رد، تغيير الحالة، وتعطيل/تفعيل الخدمة.
- **طلبات التواصل:** الفهرس يعرض بيانات الطلب والحالة وتاريخ الإنشاء والإجراء؛ show والرد فقط.
- **طلبات التجربة:** الفهرس يعرض بيانات طالب التجربة والحالة وتاريخ الإنشاء والإجراء؛ show والقبول أو الرفض. القبول يمكن أن يمرر بيانات المسؤول مسبقًا إلى إنشاء العميل.
- **الأسئلة الشائعة:** فهرس Paginated حاليًا وليس DataTable؛ نموذج موحد للإنشاء والتعديل لبيانات السؤال والإجابة والحالة عند وجودها. ينقل إلى DataTable وإحصاءات/فلاتر وفق النمط الجديد.

### الإعدادات المركزية

- **البنوك:** DataTable: تحديد، أيقونة، بيانات البنك، التفعيل، الإجراءات. نموذج Store/Update للبنك، مع Toggle.
- **دومينات التحكم:** DataTable: تحديد، بيانات الدومين، التفعيل، تاريخ الإنشاء، الإجراءات. نموذج Store/Update للدومين، مع Toggle.
- **إعدادات النظام:** صفحة إعدادات عامة وتبويبات الإعدادات العامة وإتمام ومايكروسوفت والمصادقة الثنائية. لا تعد CRUD مستقلة؛ تنقل ضمن وحدة إعدادات بخدمة وRequest لكل تبويب.

### سجل النشاط والأرشيف

- **سجل النشاط:** فهرس وshow. الخلفية القديمة تحسب إحصاءات وتقدم فلاتر؛ النقل يجعل بيانات الفلاتر من Controller ويعتمد DataTable.
- **الأرشيف:** مستخدمو الإدارة، الباقات، الكوبونات، المستأجرون، الفواتير. كل فهرس يعرض البيانات المحذوفة وتاريخ الحذف والحالة/البيانات الأساسية وإجراءات الاسترجاع أو الحذف النهائي. لا ينشأ أو يعدل منه سجل.

## إدارة المستأجر (Tenant)

### لوحة المستأجر

- **البيانات:** مؤشرات النشاط والرسم البياني وإعدادات إظهار الرسم. المحتوى خاص بالمستأجر داخل الـlayout المشترك.

### المستخدمون والأدوار والصلاحيات

- **المستخدمون — الفهرس:** تحديد، الصورة، الاسم، الرقم الوظيفي، البريد، الأدوار، الحالة، حالة الرخصة، آخر دخول، الإجراءات. يحتاج الخلفية توفير الفلاتر والإحصاءات عند النقل.
- **المستخدمون — الإنشاء/التعديل:** بيانات المستخدم، الرقم الوظيفي، البريد، الجوال، كلمة المرور، الصورة، الحالة والأدوار. صفحة منفصلة لإعادة الضبط.
- **الأدوار — النموذج:** اسم الدور وصلاحياته؛ توجد أيضًا إدارة صلاحيات منفصلة باسم الصلاحية.
- **الفجوة:** الصلاحيات لا تملك DataTable حاليًا؛ تنقل بصيغة Index موحدة فقط إن بقيت متاحة في الأعمال.

### الإسنادات

- **الفهرس:** الإحصاءات: الإجمالي، النشط، تحت المراجعة، الموقوف، والمحالة لمزاد. الجدول: تحديد، رقم الإسناد، الصورة، الاسم، التصنيف، عدد العقارات، عدد المزادات، البداية، النهاية، الحالة، الإجراءات.
- **الإنشاء والتعديل:** بيانات الإسناد وبيانات الجهة/التواريخ والحالة، مع اختيار العقارات من DataTable مستقل: تحديد، صورة، نوع، الموقع، المساحة، حالة البيانات، والحالة. الحقول الدقيقة محفوظة في Store/Update Request وتراجع عند مرحلة الإدارة لربطها بقرار الأعمال.
- **العرض:** هو المرجع البصري الذي سنعممه: تفاصيل الإسناد ثم الكيانات المرتبطة، مع زري العودة للرئيسية وتعديل البيانات.

### العقارات

- **الفهرس:** تحديد، رقم العقار، صورة، الاسم، جهة الإصدار، المدينة، النوع، المساحة، رقم الصك، حالة البيانات، حالة الإسناد، الحالة، الإجراءات.
- **الإنشاء والتعديل:**
  - أساسي: `property_number, name, type, usage_classification, area, is_active, short_description`.
  - الموقع: `latitude, longitude, city, district, administrative_region, plan_number, parcel_number, google_maps_url`.
  - الملكية: `deed_number, deed_date, issuing_authority, ownership_type, owners[][owner_name,national_id_or_cr]`.
  - الوكالة: `agent_name, agent_national_id, agency_number, agency_date`.
  - الوحدات: `units[][unit_number,unit_type,area,current_use,status]`.
  - الملفات: `main_image, deed_document, cadastral_plan, coordinates_statement, building_permit, assignment_letter_image, property_images[], additional_documents[]` و`notes`.
- **الفجوة:** الواجهة القديمة تستخدم رفعًا متعددًا بسلوك قديم؛ يستبدل كله بمكوّن Tiryaq الموحد وحياة ملفات المسودات.

### المزادات

- **الفهرس:** الإحصاءات: الإجمالي، النشط، قيد التجهيز، في انتظار الاعتماد، ويحتاج مراجعة. الجدول: تحديد، الاسم، الإسناد، البداية، النهاية، عدد العقارات، الحالة، المخرجات، الإجراءات.
- **الإنشاء والتعديل:** `name, description, start_date, start_time, end_date, end_time, type, category, city, expected_properties_count, assignment_id, supervising_entity, platform_name, platform_url, notes, property_ids[]`، قوالب المخرجات `brochure_template_id, billboard_template_id, social_template_id`، ومرفقات `attachments[]`؛ و`status` في التعديل.
- **المخرجات:** صفحات بروشور ولوحة إعلانية ومنشورات اجتماعية تستعمل القوالب المركزية.

### مركز الأعمال: الشركات

- **الفهرس:** الإحصاءات: الإجمالي، النشط، غير النشط، المؤرشف، والمضاف حديثًا. الجدول: تحديد، اسم الشركة، عدد المفوضين، الحالة، نسبة المستهدف الحالية، تاريخ الإنشاء، الإجراءات.
- **الإنشاء والتعديل:** `name, logo, status, target_percentage, authorized_people[][name,phone,email,position,is_default]`.
- **العرض:** بيانات الشركة والمفوضون؛ بقية الأقسام ظاهرة كقوالب فارغة في المصدر القديم وتحتاج قرار أعمال قبل نقلها.

### الفواتير والاشتراكات

- **الفواتير — الفهرس:** تحديد، النوع، رقم الفاتورة، المبلغ، مبلغ التسوية، طريقة الدفع، الحالة، تاريخ الإنشاء، الإجراءات. العرض والدفع الإلكتروني والتحويل البنكي صفحات مستقلة.
- **الاشتراكات:** الفهرس، اشتراك جديد، تجديد، ترقية، واشتراك معلق. هي مسارات شراء/دفع وليست CRUD تقليدية؛ تحدد أعمالها قبل النقل ثم تطبق في مسار خدمة وفواتير واحد.

### تذاكر المستأجر والإشعارات

- **التذاكر — الفهرس:** رقم التذكرة، الحالة، القسم، تاريخ الإنشاء، الإجراءات. الإنشاء: `title, ticketing_sections_id, description, attachments[]`؛ العرض والرد منفصلان.
- **الإشعارات — الفهرس:** تحديد، العنوان، الرسالة، النوع، تاريخ الإنشاء، تاريخ القراءة، الإجراءات. العمليات: تعليم مقروء، تعليم الكل، حذف وحذف جماعي.

### الدومينات والتراخيص

- **الدومينات — الفهرس:** تحديد، الدومين، النوع، التفعيل، تاريخ الانتهاء، الأيام المتبقية، كود وحالة النقل، الإنشاء والتحديث، الإجراءات.
- **التشغيل:** بحث واقتراح أسماء، فحص متعدد، ربط دومين أو نطاق فرعي، نقل وتجديد، دفع، DNS وCPanel ومسح cache. هذه وحدة تكامل وليست CRUD بسيطة وتؤجل لتثبيت سياسات المزود والدفع.
- **التراخيص:** إدارة تراخيص المستخدمين والدفع؛ لا توجد واجهة CRUD مستقلة في المصدر القديم، لذا تحصر كمسار خدمة ضمن الاشتراكات عند نقلها.

### الإعدادات والسجل والأرشيف

- **الإعدادات:** عامة: `office_name, logo_text, image, maintenance_mode, breadcrumb_visibility, force_two_factor_auth`؛ الطباعة: صور الرأس/التذييل الأفقي والرأسي والتوقيع؛ SMS: `sms_provider, sms_api_key, sms_api_secret, sms_api_endpoint, sms_sender_id, sms_from_number, sms_callback_url, sms_enabled, sms_rate_limit`؛ وبريد الدعم `support_emails[]`. تضم أيضًا المصادقة الثنائية وواجهة مركز الإعدادات.
- **رمز API:** صفحة إصدار/تجديد الرمز عبر Request مخصص.
- **سجل النشاط:** فهرس وفلاتر وإحصاءات وshow وسجل أرشيفات.
- **الأرشيف:** المستخدمون، الشركات، العقارات، المزادات، الإسنادات. الفهارس تعرض البيانات الأساسية وتاريخ الحذف وتتيح الاسترجاع أو الحذف النهائي؛ دون create/edit.

## ترتيب التنفيذ المقترح بعد اعتماد تغييرات الأعمال

1. بناء أساس الـdashboard المشترك: layout، partials منفصلة لكل نطاق، مكونات DataTable/إحصاءات/فلاتر/تبديل حالة/رفع ملف/بطاقة مراجعة/مسودة.
2. إدارة المستأجر ذات بيانات الاختبار: المستخدمون والأدوار، ثم الإسنادات، العقارات، المزادات، الشركات.
3. إدارة Admin المرجعية: الباقات، العملاء، الاشتراكات، الكوبونات، مستخدمو الإدارة والأدوار، قوالب المزادات.
4. المجالات التشغيلية: الفواتير، التذاكر، الطلبات العامة، الإشعارات.
5. الإعدادات، السجلات، الأرشيفات، ثم الدومينات والتكاملات والدفع بعد اعتماد قراراتها.
6. قبل اعتماد أي إدارة: migrations وfactories وtenant test seeder، CRUD وDataTable وملفات/مسودات وصلاحيات واختبارات تكامل ومراجعة مرئية.
