# دليل حقول وعناصر التقرير النهائي — تصميم عسير

هذا الدليل يربط العناصر التي تظهر في **تقرير المزاد النهائي بتصميم عسير** بمصدرها الفعلي في التطبيق. يغطي مسار التقارير الحالية (`cycle_version = 1`)، بما فيه حقل **ملخص التقرير** المستقل `marketing[report_summary]`. ترتيب الأقسام ثابت في التصميم، لكن الصفحات المشروطة لا تظهر إلا عند وجود بياناتها، وقد تمتد الجداول والنصوص والصور إلى صفحات إضافية؛ لذلك يُستخدم اسم القسم بدل رقم صفحة ثابت.

**تصنيف المصدر:** «مدخل» قيمة يكتبها المستخدم أو يرفعها؛ «مرجعي» مأخوذة من سجل مرتبط؛ «محسوب» ينتجه النظام؛ «ثابت» نص أو رسم داخل القالب؛ «غير معروض» محفوظ أو مدعوم داخليًا لكن ليس عنصرًا ظاهرًا في مسار عسير الحالي.

## خريطة مختصرة للأقسام

| القسم | مسار الإدخال الفعلي | الثابت والمحسوب |
|---|---|---|
| الغلافان والتواصل | المزادات ← البيانات الأساسية: الاسم؛ الإعدادات: الشعار والتواصل؛ الجهات المسندة: شعار الجهة | الزخارف ثابتة، وصياغة عنوان التقرير مشتقة من الاسم |
| بيانات المزاد والتواريخ | المزادات ← البيانات الأساسية والإسناد، ثم المنصة والمشروع؛ اسم المشروع من الإسناد | تسميات ثابتة؛ يوم الأسبوع والتاريخ الهجري محسوبان |
| جدول العقارات واللوحات | العقارات: النوع والأصل والصك؛ المزادات ← العقارات المرتبطة؛ طلب إقامة المزاد ← بيانات العقار: عدد اللوحات والمقاس | رؤوس الجدول ثابتة؛ ترتيب العقار آلي |
| المقدمة والملخص | المزادات ← التقارير والمرفقات ← مقدمة التقرير، ثم ملخص التقرير | الملخص نص مستقل؛ امتداد النص إلى صفحات متابعة آلي |
| التخطيط والإعداد والترويج | المزادات ← التسويق: المنهجيات ونطاق الحملة الجغرافي | أقسام متتابعة تحت «منهجية أعمال التسويق» بخلفية موحدة؛ تمتد إلى صفحات عند امتلاء مساحة المحتوى |
| تركيب اللوحات والكتيب | المزادات ← التسويق: التفاصيل والروابط ومرفقات الكتيب؛ طلب إقامة المزاد: صور تركيب اللوحات | أرقام الصور محسوبة؛ عناوين القسم والروابط ثابتة |
| منصة المزاد | المزادات ← المنصة والمشروع: المنصة والرابط والملاحظات؛ التسويق: لقطات المنصة | عدد العقارات والمدة والتواريخ والحالة من بيانات المزاد |
| الفيديو وX وواتساب | الحملات ← تبويب القناة ← الإحصاءات والرابط والأدلة | الأرقام مدخلة؛ نسب رسم واتساب محسوبة؛ الشعارات والتسميات ثابتة |
| التواصل الاجتماعي وجوجل | الحملات ← سناب شات / تيك توك / X؛ جوجل ← عدد المشاهدات | إجمالي مشاهدات التواصل محسوب؛ إحصاء جوجل مخفي من التقرير حاليًا بطلب المستخدم |
| الوسطاء وفك اللوحات | المزادات ← التسويق: اسم وملف كل وسيط ونص التعاقد؛ إقفال المزاد ← تعديل العقار ← صور فك اللوحات | الزخارف والعناوين ثابتة؛ ترتيب الصور آلي |
| الأصول المباعة وغير المباعة | إقفال المزاد ← تعديل العقار ← النتيجة والسعر والمشاركون والمزايدات وسبب عدم البيع | أعداد النتائج ومجموع المبيعات محسوبة؛ رؤوس الجداول ثابتة |

الجدول يصف **البيانات المعروضة المدعومة**؛ تعبئة جميع حقول الواجهة لا تعني أن جميعها تُطبع. راجع جدول «مدخلات محفوظة لا تظهر حاليًا في عسير» في نهاية الدليل، حتى عند استخدام مثال اصطناعي ممتلئ بالبيانات.

## أين تُدخل البيانات؟

| الرمز | المسار الفعلي في الواجهة | الاستخدام |
|---|---|---|
| أ1 | المزادات ← إضافة/تعديل ← **البيانات الأساسية والإسناد** | الاسم، الوصف، الإسناد، تاريخا ووقتا البداية والنهاية |
| أ2 | المزادات ← إضافة/تعديل ← **المنصة والمشروع** | منصة المزاد، رابط المزاد على المنصة، اسم مدير المشروع، ملاحظات المنصة |
| أ3 | المزادات ← إضافة/تعديل ← **العقارات المرتبطة** | اختيار العقارات التابعة للإسناد لربطها بالمزاد |
| أ4 | المزادات ← إضافة/تعديل ← **التسويق** | المنهجيات والنطاق الجغرافي والكتيب واللوحات والوسطاء؛ خطوة مستقلة مفعلة داخل نموذج المزاد |
| أ5 | المزادات ← إضافة/تعديل ← **التقارير والمرفقات** | مقدمة التقرير، ثم ملخص التقرير، وصورتا غلاف المزاد والتقرير والملفات العامة |
| ح | **الحملات التسويقية** ← إضافة/تعديل ← اختيار المزاد وأنواع الحملات ← فتح تبويب النوع | سبع قنوات فقط: يوتيوب، X، سناب شات، تيك توك، واتساب، جوجل، رابط أدلة التسويق؛ ووصف موحد لحملات التواصل أعلى التبويبات |
| إ | **طلب إقامة المزاد** ← بيانات العقارات | عدد اللوحات ومقاسها وصور تركيبها والقيمة الافتتاحية لكل عقار؛ الموافقة على إقامة المزاد تخص هذا الطلب |
| ق | **إقفال المزاد** ← تعديل ← جدول «نتائج وتفاصيل عقارات المزاد» ← زر تعديل العقار | نافذة «نتيجة إقفال العقار»: نتيجة البيع وأرقامها وصور فك اللوحات؛ يلزم حفظ النافذة ثم حفظ نموذج الإقفال |
| ع | **العقارات** ← إضافة/تعديل | بيانات الأصل مثل النوع ورقم الأصل ورقم الصك |
| س | **الإسنادات** ← إضافة/تعديل | اسم الإسناد والجهة المسندة المرتبطة |
| ج | **الجهات المسندة** ← إضافة/تعديل | شعار/صورة الجهة المسندة |
| ض | **الإعدادات** | شعار الشركة وبيانات التواصل في تقارير المزادات |
| ت | تفاصيل المزاد ← **ملفات وتقارير المزاد** ← «تحميل تقرير المزاد» | تنزيل النسخة المولدة من التقرير؛ تحديث الإعدادات وحده لا يغيّر ملف PDF سابقًا، وتُستخدم القيم الحالية عند إعادة التوليد |

> ملف `step4-settings.blade.php` وحقول `report-property-result.blade.php` القديمة **ليسا خطوة إدخال مركبة في نموذج المزاد الحالي**. خطوة التسويق المفعلة هي `step4-marketing.blade.php`؛ أما الحملات والإقفال وطلب الإقامة فلها شاشاتها المستقلة. أسماء ملفات الخطوات التاريخية لا تحدد رقم الخطوة الحالية؛ المرجع هو تضمينات `_form.blade.php` الفعلية.

تُحفظ نصوص أ4 في `auction.marketing_data`، وتُحفظ مرفقات الكتيب والمنصة والوسطاء كمرفقات مباشرة للمزاد دون إنشاء حملات لهذه الأقسام. نطاق الحملة قائمة مناطق تُدمج نصيًا في لقطة التقرير. وصف التواصل الموحد `social_context` يُدخل في جذر نموذج الحملات، ثم يُحفظ في بيانات تسويق المزاد. اكتمال البيانات يقيس خطوات المزاد الأولى حتى التقارير والمرفقات، ويظل مستقلًا عن حالة دورة المزاد وعن اكتمال إحصاءات الحملات.

## الغلاف الأمامي والخلفي والعناصر المشتركة

| العنصر الظاهر | النوع / المصدر | أين تضيفه أو تعدله؟ | سلوك العرض |
|---|---|---|---|
| اسم المزاد الكبير على الغلاف الأمامي | مدخل `auction.name` | أ1 ← «اسم المزاد» | يظهر كما سُجل |
| «التقرير النهائي لمزاد …» | ثابت + محسوب `subtitle` | جزء الاسم من أ1؛ الصياغة من القالب | إذا بدأ الاسم بكلمة «مزاد» تُضبط الإضافة لتجنب تكرارها |
| شعار الجهة المسندة أعلى الغلاف الأمامي | مرجعي `assignment.issuingEntity.image` | ج ← «الشعار أو الصورة»، ثم ربط الجهة في س واختيار الإسناد في أ1 | ليس صورة الجهة المشرفة المكتوبة في نموذج المزاد؛ يُحذف موضع الصورة عند غياب الشعار في التقارير الحالية |
| شعار الشركة في الغلافين | مرجعي `settings.image` | ض ← «شعار الشركة» | يُعرض الشعار المرفوع؛ لا يُكتب اسم الشركة مكانه تلقائيًا |
| هاتف التواصل في الغلافين | مدخل `settings.report_phone` | ض ← «بيانات التواصل في تقارير المزادات» ← «هاتف التواصل» | عند صحة الرقم يصبح رابط اتصال `tel:`؛ القيمة الفارغة لا تظهر |
| الرقم الموحد في الغلافين | مدخل `settings.report_unified_phone` | ض ← «الرقم الموحد» | نفس سلوك الهاتف |
| حساب التواصل الاجتماعي في الغلافين | مدخل `settings.report_social` | ض ← «حساب التواصل الاجتماعي» | يظهر النص المسجل؛ يصبح رابطًا إذا كان عنوان HTTPS صالحًا، وإلا يظل نصًا |
| رموز الهاتف والتواصل | ثابت | لا يوجد حقل إدخال | أصول رسومية ضمن التصميم، وليست صورًا ترفع لكل مزاد |
| خلفيات الغلافين والأشكال والخطوط والزخارف والألوان | ثابت | لا يوجد حقل مستخدم لتعديل التصميم | الغلاف الأمامي فاتح والخلفي داكن؛ مصدر الزخارف ملفات SVG وCSS الخاصة بعسير |
| اسم المزاد وعنوان التقرير وشعار الجهة المسندة على الغلاف الخلفي | غير معروض | لا يوجد إدخال منفصل | الغلاف الخلفي الحالي يحتوي شعار الشركة وبيانات التواصل والزخارف فقط |
| صورة خلفية الصفحات الداخلية | مدخل `auction.report_image` | أ5 ← «صورة غلاف التقرير» | تستخدم خلفية للصفحات الداخلية، رغم تسمية الحقل «غلاف»؛ تظهر خلف اللوحات الملونة للقالب |
| الألواح الملونة الداخلية وحدودها ومواضع النصوص والصور | ثابت | لا يوجد حقل إدخال | عناصر CSS ثابتة؛ المحتوى الداخلي هو المتغير |
| خلفية إطارات الصور والفراغ حول الصورة | ثابت | لا يوجد حقل إدخال | شفافة لتظهر خلفية الصفحة حول الصور الأصغر من الإطار؛ الألوان الموجودة داخل ملف الصورة نفسه تظل جزءًا من الصورة |
| شعار الشركة في صفحة المقدمة وبطاقة المنصة وعقود الوسطاء | مرجعي | ض ← «شعار الشركة» | نفس مصدر شعار الغلاف؛ ليس شعارًا مستقلًا لكل قسم |
| عناوين الصفحات والأقسام وأرقامها الزخرفية الظاهرة | ثابت | لا يوجد حقل إدخال | مثل «ملخص التقرير»، «منهجية أعمال التسويق»، «مخرجات المزاد»؛ عنوانا «بيانات المزاد» و«مقدمة التقرير» موجودان بنيويًا لكن CSS يخفيهما بصريًا في هذين القالبين |
| عنوان التسويق الطويل | ثابت | لا يوجد حقل إدخال | «خطة التسويق بحسب متطلبات دليل أعمال وكلاء البيع» |
| أرقام أقسام التسويق | ثابت | لا يوجد حقل إدخال | اللوحات `01`، الكتيب `02`، المنصة `03`، الفيديو `04`، X `05`، واتساب `06`، التواصل `07`، الوسطاء `09`، الفك `10`؛ هذه أرقام تصميم وليست أعداد الحملات أو الصفحات |
| التفاف النص وامتداد الأقسام وتكرار رؤوس الجداول | محسوب | لا يوجد إدخال مباشر | يتحدد بحسب طول النص وعدد العقارات والصور، ولا يعني تكرار الإدخال |

## بيانات المزاد والتواريخ وجدول العقارات

هذه الصفحة بيانات تعريفية وجدول عقارات، وليست فهرس عناوين يدويًا، حتى لو كان اسم القالب الداخلي `asir-index`.

| العنصر الظاهر | النوع / الحقل | أين تضيفه أو تعدله؟ | طريقة استخراجه |
|---|---|---|---|
| اسم المشروع | مرجعي `assignment.name` | س ← «اسم الإسناد»؛ اختيار الإسناد في أ1 | لا يأتي من حقل مستقل باسم «اسم المشروع» في أ2 |
| اسم المزاد | مدخل `auction.name` | أ1 ← «اسم المزاد» | نفس اسم الغلاف |
| مدير المشروع | مدخل `auction.project_manager_name` | أ2 ← «اسم مدير المشروع» | لا يأتي من حساب المستخدم الذي أنشأ المزاد |
| تاريخ بداية المزاد | مدخل `start_date` | أ1 ← «تاريخ بداية المزاد» | اليوم والشهر والسنة موزعة في بطاقة التاريخ |
| وقت البداية | مدخل `start_time` | أ1 ← «وقت البداية» | يُنسق إلى الساعة وصباحًا/مساءً |
| تاريخ نهاية المزاد | مدخل `end_date` | أ1 ← «تاريخ نهاية المزاد» | نفس تنسيق بطاقة البداية |
| وقت النهاية | مدخل `end_time` | أ1 ← «وقت النهاية» | نفس تنسيق وقت البداية |
| اسم يوم الأسبوع للبداية والنهاية | محسوب `start_weekday` / `end_weekday` | من التاريخين في أ1 | لا يختاره المستخدم منفصلًا |
| التاريخان الهجريان و«هـ» | محسوب + لاحقة ثابتة | من التاريخين الميلاديين في أ1 | تقويم أم القرى `islamic-umalqura`؛ لا يوجد حقل تاريخ هجري مستقل |
| «اسم المشروع»، «اسم المزاد»، «مدير المشروع»، «بداية المزاد»، «نهاية المزاد»، «الموافق»، «يوم» | ثابت | لا يوجد حقل إدخال | عناوين وتعليقات توضيحية حول القيم |
| ترتيب «م» في جدول العقارات | محسوب `position` | ترتيب العقارات المرتبطة في بيانات التقرير | رقم تسلسلي داخل قائمة المزاد؛ مختلف عن رقم الأصل |
| نوع العقار | مرجعي `property.type_label` | ع ← «نوع العقار»، ثم أ3 لربط العقار | يظهر اسم النوع المقروء |
| رقم الصك | مرجعي `property.deed_number` | ع ← «رقم الصك»، ثم أ3 | لا يُكتب مرة أخرى في التقرير أو الإقفال |
| رقم الأصل | مرجعي `property.property_number` | ع ← «رقم الأصل»، ثم أ3 | ليس المعرّف الداخلي `id` ولا ترتيب الصف |
| عدد اللوحات | مدخل مرتبط بالعقار `board.count` | إ ← بيانات العقار ← «عدد اللوحات» | المصدر الحالي `properties[].board_count` في طلب الإقامة؛ تُستخدم بيانات العلاقة القديمة عند غياب القيمة |
| مقاس اللوحات | مدخل مرتبط بالعقار `board.dimensions` | إ ← بيانات العقار ← «مقاس اللوحات» | المصدر الحالي `properties[].board_dimensions`؛ نص حر وليس أبعاد ملف الصورة بالبكسل |
| رؤوس جدول العقارات | ثابت | لا يوجد حقل إدخال | «م»، «نوع العقار»، «رقم الصك»، «رقم الأصل»، «عدد اللوحات»، «مقاس اللوحات» |

## المقدمة والملخص والتخطيط والإعداد والترويج

| القسم / العنصر | النوع / الحقل | أين تضيفه أو تعدله؟ | ما الذي يظهر؟ |
|---|---|---|---|
| مقدمة التقرير | مدخل `marketing.introduction` | أ5 ← «مقدمة التقرير» | النص المسجل المطلوب في النموذج؛ لا يُستبدل بوصف المزاد |
| عرض المقدمة وشعارها | تخطيط مرجعي + متابعة آلية | لا يوجد حقل لاختيار عرض النص أو تكرار الشعار | الشعار الكبير يمينًا بإطار نحو `248 × 414 pt`، والنص في عمود يسار بعرض `320 pt`. يحافظ النص القصير على موضع المرجع؛ مع النص الأطول تمتد منطقة النص المتاحة إلى أعلى قبل إنشاء متابعة حقيقية، ويظهر الشعار في الصفحة الأولى فقط |
| ملخص التقرير | مدخل مستقل `marketing.report_summary` | أ5 ← **«ملخص التقرير» مباشرة بعد «مقدمة التقرير»** | نص الملخص فقط؛ لا يُستنتج من المدينة أو نطاق الحملة، ولا يُملأ بمقدمة التقرير أو وصف المزاد |
| غياب الملخص | شرط عرض | اترك «ملخص التقرير» فارغًا إذا لم يوجد ملخص | لا تُنشأ صفحة ملخص فارغة ولا يُستخدم `city_context` بدلًا منه |
| التخطيط والاستعداد | مدخل `marketing.planning_methodology` | أ4 ← «منهجية التخطيط» | وصف التخطيط الذي يكتبه المستخدم، دون ادعاء تنفيذ تلقائي |
| الإعداد والتصميم | مدخل `marketing.brochure_methodology` | أ4 ← «إعداد الكتيب والهوية البصرية» | وصف إعداد الكتيب والهوية |
| شرح اختيار اسم المزاد | قديم `name_context` | **لا يوجد له حقل في شاشة الحملات أو نموذج المزاد الحالي** | تقبله آلية النصوص في اللقطات القديمة؛ لا يُقدَّم كحقل يستطيع المستخدم الحالي تعبئته |

## قنوات الفيديو وX وواتساب والتواصل وجوجل

الأرقام الآتية **إحصاءات يدخلها المستخدم** في شاشة الحملات، باستثناء الإجماليات والنسب المعلّمة بأنها محسوبة. التقرير لا يتصل بهذه المنصات لجلب الأرقام، ولا يستخرجها تلقائيًا من الصور. الاسم التقني أدناه هو مفتاح `campaigns[نوع الحملة][metrics][الحقل]` ما لم يذكر خلاف ذلك. لا توجد قنوات حالية للتخطيط أو الترويج أو الكتيب أو المنصة أو اللوحات أو الوسطاء؛ مصادرها موضحة في خطوات المزاد وطلب الإقامة أعلاه.

| القناة / الحقل | مكان الإدخال في ح | مكانه وسلوكه في التقرير |
|---|---|---|
| يوتيوب — `video_context` | «يوتيوب» ← «تفاصيل الفيديو التسويقي» | وصف قسم الفيديو التسويقي |
| يوتيوب — `views` | «عدد المشاهدات» | عدد مشاهدات الفيديو؛ يظهر في سطر الملخص وجدول إحصاءات الفيديو |

| صحة الرابط | تحقق محسوب | روابط الويب القابلة للنقر تقبل HTTPS صالحًا فقط؛ الهاتف له قواعد `tel:` منفصلة |

**سلوك توزيع المحتوى:** يحافظ العرض على تكوين المرجع، ويضغط الفراغات المرنة داخل الحدود المقررة لإبقاء مجموعات الصور والبطاقات أو اسم الوسيط وملفه معًا متى اتسعت الصفحة. عند عدم كفاية المساحة تُنشأ متابعة فعلية؛ لا تُحذف الصورة الثالثة عشرة للوحة ولا يُفصل الاسم عن ملفه لمجرد فراغ قابل للضغط. يبقى الفيديو أو المنصة ذو الرابط وحده قسمًا صالحًا للعرض دون اختلاق صورة أو إحصاءات.

**حدود الربط الحالية:** مقاييس تيك توك التفصيلية، رابط أدلة التسويق وأدلته في مسار عسير الحالي، رابط اللوحات وبعض حقول الإقفال لا تظهر جميعها كما توضح الجداول. لا يتضمن تحديث التخطيط إصلاحًا لمسار أدلة التسويق أو إضافة جدول لمقاييس تيك توك التفصيلية. تاريخ واتساب يُربط بتاريخ الحملة الخاصة بالصفحة، والنطاق الجغرافي يظهر في التخطيط. إحصاء جوجل مخفي حاليًا بطلب المستخدم؛ صفحات فك اللوحات تعتمد على الصور المسجلة بعد حفظ الإقفال.

**ملاحظة تدقيق خارج إصلاح العرض:** رُصد أن حذف آخر صف وسيط في نموذج التعديل قد يترك مفتاح `marketing.brokers` غائبًا، فيحتفظ الحفظ بالقائمة القديمة. هذه ملاحظة عن مسار الإدخال والحفظ، وليست إصلاحًا منجزًا ضمن استعادة تخطيط التقرير.

**عن الأمثلة:** صور وأسماء وأرقام ملف المثال التجريبي بيانات اصطناعية للعرض، وليست دليلًا على بيانات مزاد حقيقي أو حملة منفذة. لا تستخدمها كقيم افتراضية لبيانات المستخدم، ولا تستنتج منها وجود حقل غير موجود في الواجهة.

## مدخلات محفوظة لا تظهر حاليًا في عسير

هذا جدول تجميعي للفجوات الحالية، وليس قائمة حقول إضافية مطبوعة في المثال. قد تكون القيم محفوظة وقابلة للاستخدام في شاشة أخرى أو تصميم آخر، لكن **لا يجوز الادعاء بأنها تظهر في PDF عسير الحالي**.

| المدخل المحفوظ | مكان إدخاله الحالي | حدود عرضه في عسير |
|---|---|---|
| تيك توك: `reach`، `profile_views`، `profile_change`، `reach_change`، `views_change` | الحملات ← تيك توك | البطاقة الحالية تعرض `views` أو بديله `impressions` فقط؛ لا تضيف جدولًا لهذه القيم |
| رابط اللوحات `marketing.board_url` | المزادات ← التسويق ← رابط اللوحات | يُحفظ بدور `boards`؛ قالب صور اللوحات لا يرسمه |
| رابط أدلة التسويق | الحملات ← رابط أدلة التسويق ← رابط الحملة | يُحفظ بدور `marketing_evidence`؛ مسار صفحات عسير الحالي لا يرسم له قسمًا مستقلًا |
| تاريخ الإقفال، تاريخ فك اللوحات، تفاصيل نتائج المزاد | شاشة إقفال المزاد الرئيسية | لا تُطبع كقيم أو فقرة في عسير؛ حفظ الإقفال يسمح بإظهار أقسام النتائج والفك |
| اسم من تمت الترسية عليه، ملاحظات النتيجة | إقفال المزاد ← تعديل العقار | محفوظان؛ لا يدخلان أعمدة نتائج عسير الحالية |
| صورة غلاف المزاد، الملفات الإضافية العامة | المزادات ← التقارير والمرفقات | الصورة تخص المخرجات؛ الملفات العامة ليست أدلة حملة مصنفة للتقرير |
| المدينة، النوع، التصنيف، الجهة المشرفة، العدد المتوقع | خطوات بيانات المزاد والمنصة | لا تطبع جميعها كحقول مستقلة في عسير؛ العدد الفعلي والتفاصيل المعروضة لهما مصادر موضحة أعلاه |
| اسم الشركة والنص بجانب الشعار والتوقيع والختم | الإعدادات | لا تطبع كنصوص أو توقيع/ختم مستقل في عسير؛ الشعار صورة مرفوعة |
| اسم العقار والمساحة والمدينة والحي والصورة والقيمة التقديرية | العقارات ← إضافة/تعديل | ليست أعمدة جداول تعريف/نتائج عسير الحالية، ولا تصبح الصور أدلة تركيب أو فك تلقائيًا |

أما `name_context` وخصائص تحرير الاقتصاص وتسمية الدليل العامة والحقول القديمة للوسيط الأول/الثاني فهي **إمكانات أو توافق بيانات قديمة دون حقول إدخال حالية مطابقة**؛ لا تندرج تحت الادعاء بأن كل حقول الواجهة عُرضت. عناوين المعارض العامة وملحقات الحملات القديمة لا تُضاف إلى قائمة العناصر المرئية في المثال الحالي إلا إذا أنشأها مسار الصفحات فعلًا.

## حفظ البيانات ودورة المزاد

تعديل النصوص أو الملفات يتم من الشاشة المالكة لها: بيانات التسويق المباشرة من نموذج المزاد، واللوحات والقيمة الافتتاحية من طلب الإقامة، وإحصاءات القنوات من الحملات، والنتائج والفك من الإقفال. لا يُعاد إدخال رقم الموافقة أو سعر الافتتاح عند الإقفال. قد يُحفظ الإقفال بنتائج جزئية؛ تتحول الحالة إلى مغلق عند اكتمال النتائج المقررة لجميع العقارات، وتُبنى عندها اللقطة النهائية. وجود سجل إقفال يسمح بإظهار النتائج المسجلة وصور الفك وفق شروط الصفحات، لكنه ليس مرادفًا لاكتمال بيانات المزاد.

حذف المرفقات المباشرة أو استبدالها جزء من حفظ النموذج؛ يتحقق الحفظ من انتساب المرفقات للمزاد/القناة، وتؤجل إزالة الملفات القديمة من التخزين إلى ما بعد نجاح المعاملة. استعادة مساحات التصميم لا تعيد حقول الحملات المنقولة أو مدخلات الإقفال الملغاة، ولا تغير مصادر البيانات أو تعريف اكتمالها.
