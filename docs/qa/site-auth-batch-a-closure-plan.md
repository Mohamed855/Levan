# Batch A closure plan — 2026-11-04

التكليف: Codex ينفذ الإصلاح والتحقق حتى إغلاق 2FA-01..24، مع حفظ أعمال الإدارات الأخرى وبقية دفعات QA-001 دون تغيير. المرجع ومعايير القبول: site-auth.md وسجل site-auth-batch-a-acceptance.md.

## التنفيذ والتحقق

- [ ] إعادة إنتاج A4-01 باختبارات النافذة التالية في النطاقات الثلاثة، ثم إصلاح تكامل مزود TOTP داخل التطبيق دون تعديل vendor أو تضييق نافذة القبول. استخدام الخطوة المطابقة وحجز الاستهلاك ذريًا، مع فصل الأسرار في مفاتيح cache وعدم تخزينها نصيًا.
- [ ] إعادة إنتاج A3-01 بفحص معالج الواجهة الفعلي، ثم ترك resetButtonLoading ينظف الحالة بالترتيب الصحيح مرة واحدة. تأكيد صلاحية إعادة المحاولة وعدم تكرار POST.
- [ ] استكمال اختبارات الخادم للـguest/guard والحساب الآخر، وسياسات الفرض، والإلغاء وremember وتجديد الجلسة، وتغير الأهلية أثناء pending، وعزل path/domain وreset ذي الصلة. اختبار كل نتيجة فعلية وإصلاح أسباب أي إخفاق داخل الدفعة.
- [ ] تشغيل Laravel محلي منفصل على SQLite وsession/cache تجريبية، مع حسابات ومجالات اصطناعية؛ لا تغيير قواعد العمل أو مستخدميها. لا endpoints مصطنعة لقبول المصادقة، ولا خادم Node يولد auth أو validation.
- [ ] استخدام Firefox عبر CUA لاختبار click/Enter/paste/الصفر الأول والتبديل والأخطاء وإعادة المحاولة والإعداد/QR/recovery/disable/cancel، مع فحص RTL والأحجام 360/390/768/1440، وحفظ أدلة لا تتضمن أسرارًا.
- [ ] تشغيل اختبارات auth المعزولة، وPHP lint، وnpm run build عند تعديل الأصول. مراجعة الفروق والأمان ومطابقة الحالات الأصلية الـ24 قبل تغييرها إلى verified. يبقى أي مانع حقيقي موثقًا ولا يسجل كنجاح.

## حدود الملفات

مزود التطبيق وربطه، صفحات ومشترك 2FA عند الحاجة، resolver/controllers/requests/middleware للمصادقة ذات الصلة فقط، اختبارات auth، وأدلة وملفات docs/qa الخاصة بالدفعة. لا تعديلات على الأدوار أو المزادات أو طلبات الـtester، ولا commit أو إرسال إلى Gemini ضمنيًا.
