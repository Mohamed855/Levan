# الدفعة A — فحص الواجهة للمستخدم

تاريخ التسليم: 2026-11-04، Africa/Cairo. اختار المستخدم: «اكتفِ بالخادم وجهّز خطوات فحص الواجهة لي». هذه قائمة التنفيذ المتبقية؛ **لم ينفذ Codex هذه الخطوات في المتصفح ولم يسجلها ناجحة**. نتيجة الخادم والأدلة في [تقرير الإغلاق الخادمي](site-auth-batch-a-backend-closure.md).

## التجهيز مرة واحدة

1. استخدم النسخة الحالية من المشروع وحسابات اختبار: Admin، ومستخدم Tenant، ومستخدم آخر لاختبار الفصل. جهز Tenant A وB، ونسخة دخول بالدومين إذا كانت مهيأة.
2. افتح DevTools: تبويبا Network وConsole، مع Preserve log. طلبات form-validation/validate ليست تسجيل دخول؛ عند عد الإرسال احسب **POST النهائي** إلى two-factor-challenge أو confirmed-two-factor-authentication فقط.
3. جهز تطبيق Authenticator لمسح QR. رمز تأكيد الإعداد يُستهلك أيضًا؛ عند تسجيل الدخول بعده استخدم الرمز الجديد التالي في التطبيق، أو كود recovery غير مستخدم.
4. اختبر الحالات في النطاقات الثلاثة أدناه. إن لم يوجد دومين اختبار مهيأ، سجله blocked مع السبب؛ لا تسجل نجاحه اعتمادًا على نسخة المسار.
5. نفذ فحوص الشكل بعروض 360 و390 و768 و1440px. احفظ لقطات للحقول والروابط والأخطاء فقط؛ لا تحفظ QR أو السر أو الأكواد أو cookies في الأدلة.

| النطاق | بدء الدخول | إعدادات 2FA | التحدي بعد كلمة المرور |
| --- | --- | --- | --- |
| ADMIN | `/superadmin/login` | `/superadmin/two-factor-authentication` | `/superadmin/two-factor-challenge` |
| TENANT-PATH | `/{tenantId}/login` ثم صفحة الدخول المشتركة | `/{tenantId}/two-factor-authentication` | `/{tenantId}/two-factor-challenge` |
| TENANT-DOMAIN | `https://{tenantDomain}/login` | `https://{tenantDomain}/two-factor-authentication` | `https://{tenantDomain}/two-factor-challenge` |

المضيف المعتاد للتطوير المركزي `http://localhost:8000`؛ استخدم المضيف الفعلي للمشروع. لا تفتح HTML محفوظًا أو خادم المحاكاة القديم. سجل اسم المضيف ومعرّف حساب الاختبار دون كلمة المرور.

## التنفيذ وتسجيل النتيجة

الترتيب العملي: الإعداد 13–14، ثم 16، ثم رحلة التحدي 01–11 والعرض، ثم 19–22 و24، وأخيرًا التعطيل 17 والفرض 18. كل خلية تبدأ not_run؛ غيّرها إلى passed أو failed أو blocked، وأضف التفاصيل أسفل الجدول. Codex يعتمد الحالة الأصلية بعد مراجعة النتائج.

| --- | --- | --- | --- | --- |
| 2FA-01 | بعد كلمة المرور، أدخل TOTP حاليًا واضغط تأكيد. POST نهائي واحد، دخول الحساب واللوحة الصحيحين، دون توقف أو loading دائم. | not_run | not_run | not_run |
| 2FA-02 | في محاولة جديدة أرسل بـEnter؛ ثم جرب نقرتين سريعتين في محاولة أخرى. عملية دخول واحدة فقط لكل محاولة، ولا تكرار POST نهائي أو إشعار النجاح. | not_run | not_run | not_run |
| 2FA-03 | افحص الحقل الفارغ في الأحجام الأربعة: حقل واحد، XXXXXX كامل ومتمركز، label واضح، والخطأ مرتبط بالحقل. | not_run | not_run | not_run |
| 2FA-04 | اكتب ثم الصق رمزًا كاملًا، وجرب autofill إن توفر. الترتيب LTR؛ عند توفر رمز يبدأ بصفر يبقى الصفر وتصل الأرقام الستة كاملة. لا تعتبر عدم توفر autofill نجاحًا له. | not_run | not_run | not_run |
| 2FA-05 | في TOTP وrecovery وبالأحجام الأربعة: الرجوع يمين والتبديل يسار في السطر نفسه دون تراكب أو قص أو scroll أفقي. يجوز التفاف نص الرابط داخل نصفه. | not_run | not_run | not_run |
| 2FA-06 | قارن Computed styles للرابطين: font-family/size/weight/line-height/color/text-decoration. جرب hover وTab وEnter وfocus؛ المظهر مطابق لمرجع auth-back-link. | not_run | not_run | not_run |
| 2FA-07 | املأ TOTP ثم بدّل recovery، ثم العكس، وكرر بعد ظهور خطأ. الحقل غير النشط فارغ ومعطل؛ لا يرسل اعتمادًا منافسًا، وينتقل focus للحقل الصحيح. | not_run | not_run | not_run |
| 2FA-08 | أرسل رمزًا خاطئًا ثم صححه. كرر بـrecovery. يظهر خطأ عربي مفهوم، يعود الزر صالحًا، ويبقى وضع recovery بعد خطئه؛ لا حلقة تحميل أو فقد غير مبرر للوضع. إعادة التوجيه العادية لإظهار أخطاء POST ليست وحدها فشلًا. | not_run | not_run | not_run |
| 2FA-09 | سجل الدخول بكود recovery صالح، ثم logout/login وأعد استخدامه. الأول ينجح والثاني يُرفض برسالة مرئية، ثم يقبل كودًا آخر غير مستخدم. | not_run | not_run | not_run |
| 2FA-10 | جرب recovery خاطئًا ومن حساب آخر ومن المجموعة السابقة بعد التجديد. رفض واضح بلا دخول أو 500؛ لا تعرض أكواد الحساب الآخر في الصفحة أو Console. | not_run | not_run | not_run |
| 2FA-11 | جرب فارغًا و5 أرقام وحروفًا؛ تظهر رسائل الحقول المناسبة ويصحح الإدخال دون تعليق الزر. لا يلزم إعادة اختبارات arrays/الاعتمادين اليدوية؛ اجتازها الخادم. | not_run | not_run | not_run |
| 2FA-13 | من حساب غير مفعل: enable، امسح QR، أكد برمز فعلي، حدّث الصفحة، ثم logout/login. لا تظهر الحالة مفعلة قبل التأكيد؛ تبقى مفعلة بعده ويطلب الدخول الجديد تحديًا. | not_run | not_run | not_run |
| 2FA-14 | أثناء الإعداد جرب فارغًا ثم رمزًا خاطئًا ثم صحيحًا. بعد الخطأ يعود نص الزر ويختفي spinner وتعمل إعادة المحاولة. جرب فشل الشبكة مؤقتًا ثم إعادتها. حدّث الصفحة قبل التأكيد واستكمل الإعداد؛ لا تضارب في QR. | not_run | not_run | not_run |
| 2FA-15 | كضيف افتح صفحة الإعدادات/QR ثم اخرج من الحساب وأعد زيارة URL محفوظ. لا يعرض QR أو الأكواد. بعد تبديل حسابين، اعرض الإعدادات وتأكد أنها تخص الحساب الحالي فقط. | not_run | not_run | not_run |
| 2FA-16 | بعد التأكيد اعرض/ولّد recovery: تظهر 8 أكواد مختلفة؛ جددها، وجرب القديم والجديد في دخول جديد. لا تتغير أكواد حساب آخر ولا يتعطل TOTP. | not_run | not_run | not_run |
| 2FA-17 | على حساب وسياسة غير مفروضة: عطّل 2FA، حدّث الصفحة، ثم logout/login. الحالة غير مفعلة والدخول التالي بلا challenge. لا تعتمد على إخفاء الزر وحده. | not_run | not_run | not_run |
| 2FA-18 | على حساب اختبار غير مؤكد، اختبر الفرض Central ثم company ثم tenant settings وتركيباتها حسب النطاق. dashboard يوجه للإعداد، والتأكيد والإكمال والخروج تعمل بلا loop؛ التعطيل مرفوض عند الفرض. | not_run | not_run | not_run |
| 2FA-19 | ابدأ challenge مع remember ثم اضغط الرجوع؛ جرب Back/Forward وتحديث الصفحة، ثم ادخل بحساب آخر. لا يستكمل التحدي الملغى ولا يدخل الحساب السابق، والعودة لصفحة الدخول المناسبة. | not_run | not_run | not_run |
| 2FA-20 | افتح URL التحدي في نافذة جديدة بلا جلسة، ثم كرر بعد انتهاء الجلسة. يظهر رفض/دخول مناسب دون أسرار أو stacktrace أو زر عالق. رفض السيرفر للسياق المحذوف/التالف مثبت آليًا. | not_run | not_run | not_run |
| 2FA-21 | افتح تبويبي Admin وTenant في المتصفح نفسه. ابدأ challenge بأحدهما ثم الآخر وكرر الاتجاهين. لا تكمل جلسة لوحة باعتماد الأخرى؛ الهوية النهائية صحيحة. تصادم ID نفسه مثبت آليًا أيضًا. | not_run | not_run | not_run |
| 2FA-22 | ابدأ challenge في Tenant A، ثم بدّل المسار/الدومين إلى B أو افتحه بتبويب آخر. لا دخول إلى B باعتماد A. كرر مع رحلة reset في حسابي اختبار؛ لا تغيير لحساب B بتفويض A. | not_applicable (Tenant A/B) | not_run | not_run |
| 2FA-24 | نفذ 5 محاولات TOTP خاطئة ثم السادسة. يظهر 429 مفهوم لا loading دائم؛ بعد أكثر من دقيقة تسمح الواجهة بمحاولة جديدة. جرب remember: لا دخول قبل 2FA، ويستمر الحساب الصحيح بعده. | not_run | not_run | not_run |

2FA-12 و2FA-23 حالتان خادميتان معتمدتان في التقرير؛ لا يلزم تكرار مصفوفة الوقت أو تغيير قواعد البيانات يدويًا. اختبارات الهوية المتطابقة والعزل الخادمي لا تُلغى أو تُعاد بالكامل لمجرد نقص مشاهدة المتصفح.

## سجل النتيجة الذي ترسله إلى Codex

لكل إخفاق: معرف الحالة + النطاق + المتصفح والعرض + الخطوات + المتوقع + الفعلي + HTTP status + وجود خطأ Console + لقطة منزوعة الأسرار. عند نجاح مجموعة اذكر الحالات والنطاقات والأحجام التي اختبرتها فعليًا؛ لا يكفي «كل شيء تمام» لإثبات متغير لم ينفذ.

| --- | --- | --- | --- |

بعد إكمال هذا الجدول ومراجعة نتائجه تُغلق الحالات المركبة والدفعة؛ لا يعلن production_ready اعتمادًا على نجاح الخادم وحده.
