# بدء توليد التقارير بعد ظهور تفاصيل المزاد

سبب الجمود: إعداد التقارير الحالي `sync` ينفذ مهمة PDF داخل طلب الحفظ. صفحة التفاصيل أيضًا تستدعي إعادة التوليد عند فتح إصدار queued/processing بدل الاكتفاء بمتابعته.

1. تسجيل إصدار queued ببياناته عند الحفظ، دون تشغيل أو إرسال مهمة PDF في طلب الحفظ، لجميع مصادر التوليد المشتركة.
2. بدء الإصدار المنتظر من طلب حالة التقارير الذي ترسله صفحة التفاصيل بعد ظهورها. تسجيل بدء الإرسال ذريًا عبر تقدم الطابور 5% مع قفل صف المزاد، لمنع تكرار الإرسال أثناء polling. لا تغيير لمخطط البيانات.
3. استعمال طابور دائم خلفي؛ عند ضبط sync أو اتصال غير خلفي يُستخدم اتصال auction_reports الموجود. تشغيل العامل بالأسلوب الحالي مع فصل مخرجات العملية على Windows.
4. متابعة الإصدار التلقائي الموجود عند فتح التفاصيل، وعدم إنشاء إصدار إضافي بواسطة زر إعادة التوليد. الزر اليدوي يبقى لإعادة الطلب صراحة.
5. اختبارات: عدم تشغيل PDF أثناء الحفظ، بدء الإصدار مرة واحدة بعد فتح التفاصيل، تجاهل الإصدارات القديمة، وصول التقدم للحالة الجاهزة، وفحص مسارات الحملات والإقفال والتعديلات المشتركة. مراجعة مستقلة أخيرة.

لا تغيير لقوالب التقريرين أو قواعد الإقفال واللقطات أو الاحتفاظ بآخر زوج ناجح.
