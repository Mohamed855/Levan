# مطابقة الإدخال مع التقريرين الأصليين

الأرقام أعلاه أرقام الصفحات في الأصل قبل الإخفاء أو التكرار، وليست أرقامًا ثابتة في الملف المولّد.

- استُبعد نوع «أخرى» والمؤشرات العامة غير الموجودة في القالب، مثل النقرات والتفاعلات ووصول X/سناب. لا حذف لسجلات قديمة من قاعدة البيانات.
- أُزيل اختيار دور الرابط وعنوانه واسم قناة عامة من نموذج الحملة؛ الموضع يحدده نوع الحملة. تاريخ الحملة متاح للواتساب، حيث يوجد موضعه الأصلي.
- كل سجل يستخدم الصفحة الأصلية بسياقه، وتُكرر عند تعدد الحملات أو الأدلة. بيانات الوسيط والكتيب والمنصة لا تختلط بين السجلات.
- النص أو الرابط وحده يكفي لإظهار موضعه؛ الحقول الغائبة تبقى فارغة، والصفر المحفوظ يظهر صفرًا. النصوص تُفحص بسعة الموضع الأصلي قبل الحفظ لمنع فشل التوليد أو قص المحتوى.
- وجود حملة جوجل يمكن أن يُظهر صفحة موضعها الأصلي، لكن صور فك اللوحات لا تظهر قبل حفظ الإقفال.
- بيانات المشتري والموافقة والملاحظات خاصة بإجراء الإقفال المعتمد؛ لم تُبتكر لها حقول أو بطاقات داخل التقرير.
- لم تُنشأ إدارة ملفات وصور جديدة، ولم يتغير تصميم القالبين.

## التحقق النهائي

- 171 اختبارًا و1620 تحققًا ناجحًا على قواعد اختبار مركزية ومستأجر معزولة؛ لا تشغيل على بيانات العميل.
- المتصفح شغّل مكونات المنصة والتحقق المشترك، واختبر اختيار النوع والعقار، الحقول الشرطية والصفر، إرسال النموذجين، وأشرطة الجداول وأيقونات الإجراءات.
- فحص صياغة PHP لـ97 ملفًا، وفحص التنسيق والفروقات وبناء الواجهة نجحوا.
- توليد ومعاينة أربع نسخ PDF اصطناعية: دون حملات، وبحملات وبيانات جزئية ومتكررة. استُخدمت مواضع القالب الأصلية للنصوص والوسطاء وجوجل.
- مراجعة مستقلة أخيرة لم تجد مشكلة مهمة متبقية في هذه التصحيحات.
