# تسليم دورة تقارير المزادات

> استُبدلت قرارات العرض الواردة في هذا التسليم بعد رفض المستخدم لها. المرجع الحالي: [تصحيح الالتزام بالقوائم والنماذج والقالبين](2026-11-06-auction-cycle-convention-correction.md)، ويشمل قرار مواضع جوجل و«أخرى» المعلق.

الفرع: `feat/auction-report-cycle`. التغييرات محفوظة في مساحة العمل، دون commit أو نشر.

## ما تم تنفيذه

| طلب المستخدم         | النتيجة                                                                                                                                                            |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| هوية الشركة والجهة   | شعار الشركة من إعدادات tenant، وشعار الجهة من علاقة الإسناد. أزيلت شعارات المثال والنصوص التسويقية غير المستندة إلى بيانات محفوظة.                                 |
| بيانات التواصل       | حقول الهاتف والرقم الموحد وحساب التواصل في إعدادات الشركة؛ لا تُدخل من نموذج المزاد.                                                                               |
| الحملات التسويقية    | إدارة مستقلة بزر إضافة علوي؛ اختيار المزاد ثم النوع، مع مؤشرات مناسبة للقناة وروابط وأدلة وتاريخ اختياري. تدعم حملات متعددة من النوع نفسه.                         |
| تعديل الحملات وحذفها | تحديث التقريرين، بما يشمل المزادين عند نقل حملة، وإعادة تصنيف أدلتها عند تغيير نوعها.                                                                              |
| إقفال المزاد         | قائمة بجميع المزادات وزر إجراء لكل مزاد، دون زر إضافة علوي. تحفظ نتيجة كل عقار وبيانات المشتري أو سبب عدم البيع، ثم تعيد المستخدم للتفاصيل وتطلب تحديث التقريرين.  |
| تفاصيل المزاد        | جدول للحملات وملخص الإقفال ونتائج العقارات.                                                                                                                        |
| المحتوى الاختياري    | لا تُنشأ صفحات الحملات أو نتائج الإقفال قبل حفظ بياناتها. الصفر قيمة مسجلة؛ القيمة غير المتاحة لا تتحول إلى صفر.                                                   |
| قائمة التقارير       | صفّان منطقيان ثابتان لكل مزاد، وحالة محتوى مستقلة عن حالة تجهيز PDF.                                                                                               |
| الانتهاء             | إقفال محفوظ، وعقار واحد على الأقل، وجميع العقارات مباعة. يُقفل المزاد وحملاته وإقفاله، وتثبت بياناته في لقطة.                                                      |
| إعادة التوليد        | متاحة بعد الانتهاء. تستعمل اللقطة المثبتة مع أحدث شعار وبيانات تواصل للشركة. تغيير الإعدادات وحده لا يولد تقارير.                                                  |
| النشر الآمن          | لا تصبح المحاولة منشورة إلا بعد نجاح الملفين والتحقق من أحدث إصدار تحت قفل المزاد. تظل النسخة الناجحة السابقة متاحة عند الفشل؛ تنظيف الملفات المستبدلة بعد commit. |
| الصلاحيات            | قوائم وصلاحيات الإدارات الجديدة وترقية إضافية لصلاحيات Admin دون إعادة ضبط الأدوار المخصصة.                                                                        |
| الملفات والصور       | لم تُنفذ إدارة ملفات جديدة. تُستخدم الأدلة والمرفقات القائمة، وتُستبعد الوثائق الداخلية من التقريرين.                                                              |

تفاصيل مراجعة بيانات الإدارات الموجودة: [العقارات والإسنادات والمزادات](../../../output/cycle-review/11-existing-module-data-audit.md).

## التحقق

-   آخر حزمة اختبارات مرتبطة بالتقارير والمزادات: **153 اختبارًا، 1469 تحققًا، دون إخفاق**.
-   قواعد الاختبار: `levan_report_ci_central` و`levan_report_ci_tenant` فقط؛ لم تستخدم قاعدة التطبيق الافتراضية.
-   فحص PHP لـ87 ملفًا متغيرًا، وPint، وفحص فروق Git: نجحت.
-   `npm run build`: نجح.
-   اختبار متصفح فعلي للنموذجين: الحقول الشرطية، المراجعة، الصفر، وتبديل مباع / غير مباع: نجح.
-   توليد وفحص بصري لأربعة ملفات PDF: التقريرين قبل تسجيل الحملات والإقفال، وبعد تسجيل حملتين متكررتين ونتائج بيع مختلطة. ملفات المراجعة في `output/pdf/cycle-proof`.
-   مراجعة كود مستقلة: عولجت ثلاث ملاحظات مهمة مع اختبارات إعادة إنتاج؛ إعادة مراجعتها لم تسجل ملاحظات مهمة متبقية.
-   التحقق من التزامن اعتمد على أقفال الصفوف واختبار ترتيب التقاط اللقطة ومراجعة الكود. لم يُجر اختبار حمل متعدد العمليات.
-   عزل المستأجرين تحقق بمسارات tenant والصلاحيات واختبار تبديل التخزين الخاص الموجود؛ لم يُنشأ نشر كامل بقاعدتي tenant منفصلتين.

الفحص الأوسع كشف إخفاقًا منفصلًا في `TemplateSchemaPresetsTest::test_all_sample_presets_pass_schema_validation`: عدد صفحات عينة قالب لا يطابق التحقق. ملفات هذا الاختبار ومنطق `TemplateSchema` لم تتغير ضمن هذه الدورة.

## حالة قاعدة البيانات

ترحيلات المخطط والصلاحيات الجديدة جاهزة واختُبرت في القاعدة المعزولة فقط. لم تُطبّق على بيانات العملاء الحالية. يلزم تطبيقها عبر مسار ترحيل tenant المعتمد عند تفعيل التغييرات في البيئة المطلوبة.
