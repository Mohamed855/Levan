## قرارات التصميم المقترحة

1. افتراض ينتظر تأكيد المستخدم: الحرم مرجع `outputs` وعسير مرجع `report` لكل المزادات، لا اختيار بناءً على اسم المزاد. لو كل مزاد له عائلة تصميم مختلفة يتغير ربط القالب قبل التنفيذ.
2. إعادة استخدام الرسم والهندسة الأصلية في HTML/SVG كمصدر، مع إتمام ربط النصوص والصور والجداول على الخادم داخل مسار Blade الحالي قبل HTML→PDF. محركات الحزمة JavaScript تُستخدم لمعايرة المرجع فقط، ولا تعود كمحرر/باني بيانات وقت التوليد. لا إعادة رسم تقريبية من الصفر ولا وضع صفحة PDF كاملة كصورة وكتابة البيانات فوق القديمة.
3. العناصر الثابتة كالزخارف والشعارات يجوز الاحتفاظ بها SVG/صور أصلية عالية الدقة؛ كل بيانات مزاد سابق تُزال من النصوص والرسومات والصور المركبة قبل إدخال البيانات الجديدة.
4. المصدر الهندسي والبيانات واحد للمعاينة وPDF وPNG. إعداد إخراج خاص بملفات التقارير، حتى لا تتغير صادرات البروشور/اللوحات/السوشيال.
5. افتراض للمراجعة: الرسم الرسمي ثابت افتراضيًا؛ مسألة فتح تعديله بصلاحية معلقة على إجابة المستخدم. نطاق التنفيذ الأساسي لا ينشئ إدارة جديدة أو صلاحيات جديدة أو يغير مصمم البروشور.
6. لا fallback صامت لخط مختلف ثم وصف الناتج بأنه مطابق. يمكن إنتاج نسخة مراجعة ببديل معلن؛ يمنع اعتماد المطابقة حتى يتوفر الخط المطلوب أو يوافق المستخدم صراحة على فرق الخط.

## تعريف المطابقة

**مع نفس البيانات والصور:** جميع الصفحات والأقسام موجودة وبالترتيب، نفس المقاس والمواضع والدرجات اللونية والشعارات والخطوط والجداول وقص الصور. القاعدة: لا فرق تصميمي مقبول تلقائيًا. التنعيم وفروق محرك الطباعة تسجل منفصلة بدليل قبل قبولها؛ لا ادعاء 100% من رقم similarity عام.

**مع بيانات جديدة:** نفس القواعد التصميمية، مع صفحات متابعة عند تجاوز السعة. عدد الصفحات ليس ثابتًا لكل المزادات. لا قص كلمات أو تقليص خط صامت أو تمديد صور أو تكرار صورة لسد مكان فارغ. لا تثبيت أعداد وأسعار وأسماء المرجع في الكود.

**البيانات:** قيم النتائج والإجماليات من snapshot موحد. الفرق بين صفر وعدم توفر قيمة محفوظ؛ لا اختراع مساحات أو مقاسات لوحات أو تحويل غياب البيع إلى نتيجة نهائية. تنسيق الأرقام والتواريخ والعملات مستقل عن قيمها.

## التنفيذ الهندسي

### 1. مرجع مقاس وموثق

تجميد الحزمة ببصمات ونسخة خاصة بالمشروع. استخراج manifest لكل صفحة: عرض/ارتفاع بالنقاط، خلفيات وتدرجات وألوان وتوقفاتها وشفافية، حدود وظلال، حاويات وإحداثيات وتحويلات وقص، نصوص مع baseline واتجاه ومحاذاة وتباعد وline-height، خطوط بأوزانها، جداول بترتيب أعمدتها وسعتها. الأرقام تستخرج من SVG/CSS ولا تُخمن من المعاينة. جرد كل مورد: شعار، زخرفة، قناع، صورة محتوى، صورة تحتوي نصًا.

بوابة أولى: طباعة الحزمة دون أي تعديل ومقارنة كل صفحاتها بالمصدر المعتمد. الفروق الناتجة هنا ليست أخطاء بيانات Laravel؛ تعالج قبل ربط المزادات.

### 2. الخطوط

قائمة دقيقة لكل صفحة/حقل بالاسم والوزن والملف والتغطية العربية. الحزمة تذكر GEContrastBold-Bold وNizarBBCKurdish وSTV وTheSans-Plain وTheSans-Bold؛ الباني الحالي يذكر عائلات إضافية تُدقق بدل افتراض حاجتنا لكلها. تُطلب فقط الملفات الكاملة التي يثبت استخدامها في حقول متغيرة، مع حق استخدامها وتضمينها. لا يُستنتج خط كامل من subset ولا توضع حروف جديدة مرسومة يدويًا. تُختبر التشكيلات والأرقام والاتصال والنص المختلط. الانتظار الصريح لاكتمال الخطوط والصور مطلوب قبل التصوير والطباعة.

### 3. عقد البيانات

يبقى `AuctionReportDataBuilder::build(Auction): array` مسؤول snapshot. يكتمل بتصنيف أدلة التسويق وتركيب/إزالة اللوحات والوسطاء والعقود؛ توثيق ربط الصورة بالعقار وترتيبها، الأصول/الصكوك المتعددة، عدد ومقاس اللوحات، الأوقات والتواريخ وأي نص تحريري متغير، مؤشرات ومنصات وروابط التسويق وبيانات الاتصال.

لكل حقل مرجعي يوثق مصدره الحالي أولًا: موجود/قابل للاشتقاق/ناقص/نص ثابت/صورة تحتوي نصًا. لا migration إلا لحقل ناقص مؤكد، وأي تعديل نموذج يمر FormRequest → Policy → Action/Service → UI → Tests وفق Golden Pattern. لا حفظ قيم حرجة في ملاحظات غير منظمة. النص التحريري الرسمي ثابت إن لم يحتو بيانات مزاد؛ أي اسم/تاريخ/عدد ضمنه يصبح binding. الهجري يحتاج مصدرًا/طريقة تحويل معتمدة قبل اعتماده، لا تقويمًا تخمينيًا.

### 4. الصفحات

الحرم: 1 غلاف، 2 مشروع وتواريخ وجدول العقارات، 3 مبيعات وعدم بيع، 4 تسويق رقمي، 5 لوحات، 6 وسطاء وعقود، 7 خاتمة واتصال.

عسير: 1 غلاف، 2 مشروع وعقارات وتواريخ، 3–7 تقديم ومنهجية وتخطيط وإعداد ونشر، 8–9 لوحات، 10–16 كتيب ومنصة وفيديو وشبكات اجتماعية ووسطاء، 17–18 إزالة لوحات، 19 مبيعات، 20 عدم بيع، 21 خاتمة. هذه خريطة أقسام أولية تُربط بمعرفات الحزمة الفعلية في manifest.

تبقى صفحات المنهجية موجودة بدل إسقاطها تلقائيًا. الأقسام غير المنطبقة/الناقصة تتبع قاعدة موثقة؛ النقص المانع يفسر عبر حالة فشل التوليد الحالية، بلا شاشة اعتماد أو موافقة جديدة ولا تعطيل التدفق التلقائي بطابور مراجعة. قرار حذف صفحة أو إظهار حالة فارغة يوثق ويُراجع مع المستخدم. لا يبقى اسم أو رابط أو رقم أو صورة من مزاد المصدر كحل بديل. الصور داخل screenshots تستبدل كمستند كامل، ولا يكفي تعديل binding خارجي لها.

### 5. الترقيم والتصدير

صفحات متابعة بنفس رأس وتذييل وعرض أعمدة القسم، دون صفحات تفاصيل عقار إضافية لا توجد بالمرجع. يحتفظ الصف المتعدد الأسطر بحدوده ولا يُقسم على صفحتين؛ النص الزائد يُبلّغ عنه قبل اعتماد النسخة. يحفظ crop والإحداثيات لكل صورة؛ الخلفية cover وتحكم موضعها الحاليان محفوظان. PNG لكل صفحة من نفس النسخة النهائية، مع رقم الصفحة والأبعاد والدقة؛ تنزيل كل الصفحات حسب العقد الحالي أو قرار صريح، لا لقطة صفحة أولى فقط.

تُحفظ بصمات القالب والخطوط والمحتوى وإعدادات المحرك مع إصدار التوليد حتى يمكن إعادة المقارنة. يبقى نجاح الملفين شرط ready، والحماية من نشر إصدار قديم وعزل المستأجرين وإعادة المحاولة تعمل كما هي.

## قبول وتسليم

1. مقارنة كل صفحات المرجع بالحزمة دون تغيير.
2. fixture أصلي مستقل غير قابل للتغيير، موثق لجميع bindings والصور والترتيب، لاختبار التطابق الكامل. وsnapshots منفصلة من مزادي test لاختبار البيانات المتغيرة؛ لا تستبدل حقولهما لإجبارهما على مطابقة الأصل.
3. نفس fixture عبر مسار النظام ثم عبر الحفظ الفعلي والتوليد التلقائي. تثبيت أن الملف محل المقارنة هو الملف المنزّل من الإصدار الأخير.
4. overlay وdifference لكل صفحة بدقة 300 DPI، وتفاصيل الحروف والظلال 600 DPI؛ المصدر والمولّد بنفس محرك عرض PDF ونفس المقاس. لا stretch لإخفاء فرق الورق، ولا استبعاد مناطق البيانات في اختبار تطابق البيانات الأصلية.
5. جداول فحص للألوان والإحداثيات والخطوط والمحتوى وقص الصور. الفروق تُصنف تصميم/مدخلات/خطوط/محرك، كل فرق مع موضع وسبب وحالة. فروق SSIM/البكسلات وسائل مساعدة فقط.
6. حالات متغيرة: أسماء عربية جديدة قصيرة/طويلة، صكوك متعددة، صفر/واحد/السعة/السعة+1 من الصفوف والصور، بيع كامل/عدم بيع/نتائج غير مكتملة، صور طولية/عرضية/مفقودة، قيم كبيرة، وروابط ونص مختلط.
7. التسليم: PDF وPNG، مقارنة جنبًا لجنب وoverlay وdifference لكل الصفحات، manifest بيانات ونسخ، تقرير فروق متبقية. لا إعلان «نسخة طبق الأصل» مع خط مفقود أو اختلاف محتوى أو صفحة أو لون أو موضع غير محسوم.

## أسئلة مفتوحة لا تمنع إكمال خطة المراجعة

- تأكيد علاقة الحرم بالمخرجات وعسير بالتقرير على كل المزادات.
- هل ملفات PDF الحكومية الأصلية قبل الاستخراج متاحة؟ الحزمة الحالية نقطة انطلاق وليست إثبات اعتماد حكومي.
- توفير الخطوط الكاملة المستخدمة في الحقول المتغيرة؛ إعداد قائمة طلب نهائية بعد الجرد.
- صلاحية تعديل التصميم الرسمي، وقاعدة الأقسام غير المنطبقة/الناقصة.

التنفيذ يبدأ بعد مراجعة الخطة وتثبيت القرارات المؤثرة؛ يمكن إنجاز جرد الأصول ومعايرة المحرك قبل وصول الخطوط، لكن لا يعتمد تطابق النصوص المتغيرة بدونها.
