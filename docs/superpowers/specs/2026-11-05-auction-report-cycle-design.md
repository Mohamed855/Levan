# مواصفات دورة تقارير المزادات المعتمدة للمراجعة

التاريخ: 5 نوفمبر 2026. هذا المستند يجمع قرارات المستخدم، وآخر توضيح له يعلو على أي صياغة سابقة في تقارير المقارنة.

## الهدف والنطاق

تطوير مصادر بيانات التقريرين وإدارة الحملات وإقفال المزاد وفهرس التقارير، باستخدام مكونات المنصة الحالية وأسلوب إدارة الإسنادات. إدارة الملفات والصور الجديدة خارج النطاق بالكامل. لا يُنقل تصميم الصور أو ترتيب صفحاتها أو ألوانها.

العقارات والإسنادات والمزادات تُراجع للتأكد من كفاية البيانات. لا تتضمن الموافقة حذف حقولها أو إضافة خريطة جديدة أو استيراد أو تصنيفات لم يقررها المستخدم.

## الهوية والتواصل

- شعار الشركة من إعدادات الـtenant يحل محل شعار ليفان العقارية في جميع مواضعه بالتقريرين، بما فيها الصفحات المكررة والملاحق.
- بديل شعار إنفاذ هو شعار الجهة المسندة `IssuingEntity.image`، وليس صورة مستندات الإسناد.
- اسم الشركة `office_name` والنص بجانب الشعار `logo_text` واسم الجهة المسندة **ليست مدخلات للتقريرين**؛ لا تضاف حتى كقيم اختيارية للتقرير.
- منصة المزاد ورابطه يبقيان في بيانات المزاد.
- الهاتف والرقم الموحد وحساب التواصل تُدخل في إعدادات الـtenant، وتزال حقول إدخالها من المزاد.
- لا تُنسخ قيمة عشوائية من مزاد قديم إلى إعدادات الشركة. البيانات القديمة لا تُتلف لمجرد نقل مصدر الإدخال.
- غياب شعار شركة/جهة لا يبرر إظهار شعار ليفان أو إنفاذ كأنهما الجهة الفعلية. تبقى مساحة الشعار محايدة دون اختراع هوية.

## الحملات: آخر قرار

- CRUD مستقل بسجلات حملات فعلية، لا قائمة مزادات افتراضية لكل منها زر إنشاء.
- يوجد زر «إضافة حملة» أعلى index، كما في صفحات النظام.
- يبدأ الإنشاء باختيار المزاد، ثم نوع/قناة الحملة، ثم البيانات الخاصة بها، ثم المراجعة والحفظ.
- يمكن إضافة عدة حملات للمزاد، ومنها عدة حملات لنفس النوع.
- تتغير الحقول الظاهرة حسب النوع، لا تعرض كل مؤشرات جميع المنصات في صف واحد.
- إعادة استخدام القنوات والمؤشرات والأدلة الموجودة، دون اشتراط كل القنوات على كل مزاد.
- صفحة الحملة وقسمها في PDF يظهران إذا وجدت بيانات محفوظة لها، ولا يظهر قسم بديل فارغ عند غيابها.
- قيمة صفر مدخلة صحيحة تختلف عن حقل غير مقدم.
- إضافة الحملة أو تعديلها أو حذفها يعيد توليد تقريري المزاد المتأثرين بعد نجاح الحفظ.
- إذا سمح تعديل الحملة بتغيير المزاد، يُحدّث تقريرا المزاد القديم والجديد، وتتحقق صلاحية تعديل كليهما.
- الحفظ يعيد المستخدم مباشرة إلى تفاصيل المزاد مع حالة تجهيز التقريرين.
- يضاف جدول للحملات في تفاصيل المزاد، مع إجراءات بحسب الصلاحيات وحالة انتهاء المزاد.
- أدلة الحملة تستخدم الإرفاق الحالي مع ربطها بالحملة؛ لا تنشأ مكتبة وسائط جديدة.

## الإقفال

- index يعرض المزادات منذ إنشائها، وليس الإقفالات المسجلة وحدها.
- لا زر create عام؛ الإدخال أو المتابعة من إجراء صف المزاد.
- تستخدم النماذج والمراجعة مكونات النظام الحالية.
- النتائج تخص عقارات المزاد فقط: مباعة/غير مباعة، اسم من تمت الترسية عليه وقيمتها للمبيع، سبب عدم البيع لغير المبيع، وملاحظات النتيجة.
- تُحافظ بيانات الافتتاح والمشاركين والمزايدات التي يحتاجها التقريرين؛ لا تُحذف لغيابها عن لقطة من المرجع.
- تاريخ الإقفال ورقم الموافقة بيانات إقفال مستقلة عن وقت نهاية المزاد ورقم الإسناد.
- المراجعة والحفظ يعيدان المستخدم إلى تفاصيل المزاد، ويطلبان توليد التقريرين.
- لا تظهر أقسام الإقفال والنتائج قبل وجود إقفال محفوظ.
- لا يضاف مسار اعتماد خارجي أو Word جديد؛ المعتمد إدخال ومراجعة وحفظ.
- حفظ الإقفال بكل العقارات مباعة ينهي المزاد من ناحية تعديل بيانات التقرير. إقفال يتضمن غير مبيع يبقى قابلًا للتعديل حسب الصلاحيات.

## فهرس التقارير

- index بنمط النظام، دون لوحة رسومات.
- سجلان منطقيان ثابتان لكل مزاد: مخرجات الحرم والتقرير النهائي عسير. عدد الصفوف لا يزيد مع التوليد المتكرر.
- الفلاتر والبحث والترتيب والترقيم من الخادم.
- حالات المحتوى: غير مكتمل / مكتمل / منتهي. حالة إنشاء PDF التشغيلية منفصلة.
- تفسير تنفيذي معروض للمراجعة بعد توضيح المستخدم: القنوات اختيارية، ولا توجد قائمة قنوات إلزامية عامة؛ التقرير غير مكتمل قبل حفظ بيانات حملة صالحة، ومكتمل بوجود بيانات المزاد وحملة محفوظة صالحة. حالة منتهي لها الأولوية عند حفظ إقفال كل العقارات فيه مباعة.
- لا تعتبر قائمة عقارات فارغة «كلها مباعة».
- إذا حُذفت آخر حملة قبل انتهاء المزاد، تختفي أقسامها ويعود التقرير غير مكتمل.
- لا تقفل أسماء الإعدادات أو بيانات العقار والإسناد والجهة للاستخدامات الأخرى؛ القفل يخص المزاد والحملات والإقفال.
- يمنع الخادم تعديل وحذف **سجلات المزاد المنتهي وحملاته وإقفاله**، بما فيها مسارات الحذف الجماعي وتغيير التفعيل، لا بمجرد إخفاء الأزرار. لا يتوسع هذا القفل إلى العقار أو الإسناد أو الجهة أو إعدادات الشركة المشتركة؛ بيانات التقرير النهائية محفوظة في لقطته.
- إعادة التوليد تبقى متاحة دائمًا من تفاصيل المزاد.

## التحديث التلقائي واليدوي

| الحدث | التصرف |
|---|---|
| حفظ/تعديل/حذف حملة | توليد جديد للمزادات المتأثرة بعد الالتزام بالحفظ |
| حفظ/تعديل إقفال مسموح | توليد جديد |
| تعديل بيانات المزاد المؤثرة قبل الانتهاء | توليد جديد |
| تعديل/حذف بيانات مرتبطة مؤثرة في تقرير غير منتهٍ، مثل بيانات العقار أو الإسناد أو شعار الجهة | تحديث المزادات المرتبطة المتأثرة؛ لا توليد عند تعديل حقل لا يستخدمه التقرير |
| تغيير إعدادات الشركة: شعار/تواصل | لا توليد تلقائي |
| إعادة توليد يدوية لتقرير غير منتهٍ | استخدام بياناته الحالية وأحدث إعدادات الشركة |
| إعادة توليد يدوية لتقرير منتهٍ | الحفاظ على بيانات المزاد والحملات والإقفال والمصادر المشتركة المثبتة، مع أحدث شعار وتواصل من إعدادات الشركة |
| فشل التوليد | الإبقاء على آخر زوج ملفات ناجح وإتاحة إعادة المحاولة |
| نجاح أحدث توليد | نشر الملفين الجديدين، ثم حذف ملفي الإصدار السابق الخاصين بهذا المزاد |

التثبيت بعد الانتهاء يتبع اختيار المستخدم السابق، واستخدام أحدث إعدادات الشركة في التوليد اليدوي يتبع تصحيحه الأخير. لا يعاد فتح بيانات المزاد بسبب تحديث الشعار.

## إصدار الملفات والتزامن

- تشغيل المهمة في سياق الـtenant الصحيح.
- لقطة البيانات تتضمن الصور والشعارات المستخدمة، لا مسارات قد تُحذف لاحقًا وحدها.
- نشر زوج PDF يتم بعد نجاح الملفين، ولا تنشر نتيجة قديمة فوق إصدار أحدث.
- محاولات إعادة التوليد لا تمحو آخر إصدار ناجح قبل وجود بديل صالح.
- سجلان منطقيان في القائمة لا يعني سجلين جديدين لكل إصدار تقني.
- لا يبقى تنزيل للإصدارات المستبدلة في القائمة، وتُنظف ملفاتها بعد نجاح الاستبدال.

## قرارات تنفيذية مقترحة للمراجعة

- استخدام `auction_marketing_campaigns` لسجلات الحملات مع JSON للمؤشرات المعروفة بحسب القناة.
- سجل `auction_closings` واحد لكل مزاد؛ النتائج تظل على علاقة العقار بالمزاد مع إضافة اسم المشتري وملاحظة النتيجة.
- تمثيل سجلَي التقارير في الاستعلام كنوعين ثابتين لكل مزاد، لا نسخ فهرس لكل إصدار.
- الحفاظ على `AuctionReportGeneration` كحالة تشغيل وإصدار، مع مؤشر آخر إصدار منشور ناجح.
- نسخ الحملات القديمة إلى السجلات الجديدة بطريقة قابلة لإعادة التنفيذ دون تكرار، والحفاظ على الأدلة القديمة دون نسبتها عشوائيًا لحملة عند تعدد الحملات من نفس النوع.
- المتطلبات الفنية لكل نوع حملة تتبع البيانات التي يستهلكها القالب؛ القناة والمزاد مطلوبان، ويلزم تفصيل فعلي واحد على الأقل: مؤشر ذو قيمة بما فيها صفر، أو رابط صالح، أو دليل مدعوم. المؤشرات لا تملأ بأصفار افتراضية. هذه قاعدة تحقق تنفيذية مقترحة للمراجعة، وليست اشتراطًا لكل القنوات.
- لا يضاف زر إنشاء عام للإقفال، ولا تنقل فكرة إجراء الصف القديمة إلى الحملات بعد تصحيح المستخدم.

## التحقق المطلوب

اختبارات سلوك للحالات والصفحات الشرطية وCRUD، عزل شركتين، صلاحيات القراءة والكتابة، منع التحايل على القفل، انتقال حملة بين مزادين، نجاح وفشل وتزامن التوليد، عدم زيادة صفوف الفهرس، أحدث شعار عند التوليد اليدوي، وصحة كل موضع شعار بصريًا.
