## سجل الأخطاء والملاحظات المكتشفة والحلول الجذرية (Bugs & Resolution Log)

### BUG-01: خطأ تكرار لا نهائي (RangeError: Maximum call stack size exceeded) في واجهة إنشاء وتعديل الباقات
- **المسار:** `http://localhost:8000/superadmin/plans/create` و `http://localhost:8000/superadmin/plans/{id}/edit`
- **الملف المتسبب:** [form-ui.js](file:///d:/Levan/resources/assets/js/admin/plans/form-ui.js#L103-L115)
- **النوع والشدة:** Blocker (عائق حرج).
- **السبب الجذري:** عند استماع `$select.on("change select2:select select2:clear")`، كان الكود يقوم بإعادة إطلاق حدث `this.dispatchEvent(new Event("change", { bubbles: true }))` على نفس العنصر، مما يجعل jQuery و Select2 يعيدان تشغيل الدالة ذاتها في حلقة تكرار لا نهائية تفيض الـ Call Stack.
- **الحل:** تم إصلاحه فوراً بالسماح بإطلاق `change` فقط إذا لم يكن نوع الحدث الحالي `change` (`if (e.type !== "change")`)، وإعادة بناء الأصول بنجاح.

### BUG-02: ملف مفقود (404 Not Found) للبحث الرأسي في الشريط العلوي
- **الرابط المطلوب:** `http://localhost:8000/static/i18n/search-vertical.json` و `search-horizontal.json`
- **النوع والشدة:** منخفض / تجميلي (Low / Cosmetic).
- **السبب الجذري:** كان ملف `main.js` يطلب ملف الترجمة لـ Typeahead navbar search بشكل متزامن، وبسبب عدم وجود الملفين في المجلد، كان السيرفر يرجع خطأ 404 في الـ Console في كل صفحات النظام.
- **الحل:** تم إنشاء الملفين `public/static/i18n/search-vertical.json` و `public/static/i18n/search-horizontal.json` بهيكل JSON قياسي `{ "pages": [] }`، وإضافة حماية `searchData?.pages || []` في [main.js](file:///d:/Levan/resources/assets/js/shared/basic-tamplate/main.js#L580) وإعادة بناء الأصول.

### BUG-03: خطأ اتصال WebSocket وخرق سياسة أمان المحتوى (CSP) لخدمة Reverb
- **الرابط:** `ws://127.0.0.1:8081/app/...` و `wss://127.0.0.1:8081/app/...`
- **النوع والشدة:** متوسط (Medium / Console Warnings).
- **السبب الجذري:** كانت دالة `feed` في `DashboardNotificationController` ترسل مفاتيح الاتصال بخادم Reverb دائماً حتى لو كان `BROADCAST_DRIVER=log` أو غير مفعل، مما يدفع المتصفح لمحاولة الاتصال بمنفذ Reverb 8081 غير العامل ويثير أخطاء في الـ Console والـ CSP.
- **الحل:** تم تعديل `DashboardNotificationController::feed` لترسل مصفوفة `broadcast` فقط إذا كان `config('broadcasting.default') === 'reverb'`، وإلا تُرجع `null` مما يجعل واجهة المتصفح تعتمد على آلية الـ Polling الدورية الصامتة بدون أي أخطاء.

### BUG-04: تسمية الكلاس البرمجي لزر الحذف النهائي في أرشيف المستخدمين
- **المسار:** `resources/views/admin/archive/admin_user/action.blade.php`
- **النوع والشدة:** منخفض / اتساق برمجي (Low / Consistency).
- **السبب الجذري:** استخدام كلاس مقتضب `.js-force-btn` بينما تستخدم بعض الجداول العامة كلاس `.js-force-delete-btn`.
- **الحل:** تم توحيد الكلاسات في قالب الأرشيف ليحمل كلاً من `js-force-delete-btn` و `js-force-btn` لضمان استجابة كافة معالجات الـ DataTables بسلاسة.

### BUG-05: عدم إسقاط قاعدة بيانات المستأجر وحذف ملفاته عند الحذف النهائي (Force Delete)
- **المسار:** `app/Services/Admin/Companies/CompanyService.php` و `app/Services/Shared/Cpanel/CpanelService.php`
- **النوع والشدة:** عالي / سلامة البيانات والموارد (High / Resource Leak).
- **السبب الجذري:** كانت دالة `forceDeleteCompany` تكتفي بحذف الاشتراكات والإعدادات واستدعاء `$company->forceDelete()`، دون إسقاط قاعدة بيانات MySQL الخاصة بالـ Tenant (`DROP DATABASE`) ودون حذف مجلدات التخزين `storage/app/tenants/{id}` و `public/tenants/{id}`، مما يترك قواعد بيانات وملفات معلقة في الخادم بعد الحذف النهائي.
- **الحل:** تم إصلاحه عبر تزويد `CpanelService` بدالة `deleteDatabase` لتعمل محلياً وعبر cPanel API، ودمج إسقاط قاعدة البيانات ومحو مجلدات التخزين ضمن عملية الحذف النهائي في `CompanyService`.
