## 2. تفاصيل المعالجات الفنية للأدلة المستقلة (`R-01` إلى `R-03`)

### المعالجة R-01: عزل `DROP DATABASE` عن معاملات MySQL
- **التشخيص:** أوضح تقرير المراجعة المستقلة أن استدعاء `DB::statement('DROP DATABASE ...')` داخل `DB::transaction()` يؤدي إلى قيام خادم MySQL بإنهاء المعاملة فوراً وبشكل ضمني ([MySQL Implicit Commit](https://dev.mysql.com/doc/refman/8.4/en/implicit-commit.html)). عند محاولة Laravel إغلاق المعاملة عبر `DB::commit()` يُطلق الخطأ المسجل في `storage/logs/laravel.log`: `Error force deleting company: There is no active transaction`.
- **التنفيذ البرمجي في `app/Services/Admin/Companies/CompanyService.php`:**
  تم فصل العملية إلى مرحلتين متعاقبتين:
  1. مرحلة المعاملة لقاعدة البيانات المركزية (`DB::connection('mysql')->transaction(...)`): تتولى حذف سجلات الاشتراكات والفواتير والتذاكر وإعدادات الشركة، ثم حذف سجل المستأجر من جدول `companies` و `tenants`.
  2. مرحلة ما بعد إتمام المعاملة بنجاح (Post-Transaction Resource Purge): استدعاء `CpanelService::deleteDatabase()` لحذف قاعدة المستأجر، ثم حذف مجلدات التخزين.
- **الإثبات:** تم تشغيل سكربت التحقق `scratch/test-tenant-deep-purge.php` على مستأجر تجريبي، وأكد الفحص اختفاء قاعدة البيانات وسجل المستأجر مع تسجيل `0` أخطاء في `laravel.log` وزوال استثناء "There is no active transaction" نهائياً.

### المعالجة R-02: تنظيف التخزين الخاص `storage/app/tenants-private/{id}`
- **التشخيص:** تبين أن مسارات ملفات النماذج التنظيمية وتقارير المزادات ومرفقات طلبات الإقامة تُخزن في مجلد التخزين الخاص المضبوط في `app/Providers/TenancyServiceProvider.php` تحت المسار `storage/app/tenants-private/{tenant_id}`، بينما كان كود الحذف السابق يكتفي بتنظيف `storage/app/tenants/{id}` و `public/tenants/{id}` فقط.
- **التنفيذ البرمجي:**
  تم تحديث `CompanyService.php` لإضافة مسار التخزين الخاص:
  ```php
  $privatePath = storage_path('app/tenants-private/' . $company->id);
  if (File::exists($privatePath)) {
      File::deleteDirectory($privatePath);
  }
  ```
- **الإثبات:** تم فحص مسار `storage/app/tenants-private/` بعد تنفيذ الحذف النهائي للمستأجر، وتأكد زوال المجلد الخاص بمستنداته تماماً دون أي تسرب للملفات.

### المعالجة R-03: حماية القاعدة المركزية وفحص استجابة cPanel
- **التشخيص:** كان استدعاء `CpanelService::deleteDatabase()` يفتقر إلى التحقق من عدم استهداف قاعدة البيانات المركزية، وكان يتجاهل محتوى مصفوفة الرد القادمة من cPanel API.
- **التنفيذ البرمجي في `app/Services/Shared/Cpanel/CpanelService.php`:**
  1. **حماية القواعد المحظورة (Safety Guard):**
     ```php
     $centralDb = config('database.connections.mysql.database');
     $protectedDbs = array_filter([$centralDb, 'mysql', 'information_schema', 'performance_schema', 'sys']);
     if (in_array(strtolower($databaseName), array_map('strtolower', $protectedDbs), true)) {
         Log::critical("Security violation attempt: Attempted to drop protected central database {$databaseName}");
         return false;
     }
     ```
  2. **التحقق من حالة استجابة cPanel:**
     في بيئة الإنتاج يتم فحص `status` و `errors` في استجابة cPanel JSON API، ولا تُعتبر العملية ناجحة إلا إذا أكد cPanel إتمام حذف القاعدة والمستخدم، مع تسجيل أي تحذيرات أو أخطاء صراحةً.

   - **الأثر:** عدم استجابة نافذة التأكيد عند النقر على زر الحذف النهائي في المتصفح.
5. **BUG-05: بقاء قاعدة البيانات والمجلدات بعد الحذف النهائي للمستأجر:**
   - **الخطأ:** تنفيذ Soft Delete للبيانات دون إسقاط قاعدة بيانات المستأجر ودون تنظيف مجلدات التخزين.
   - **الأثر:** تراكم قواعد بيانات مهجورة وملفات خاصة في الخادم.
6. **BUG-06: قص نص اسم المنشأة في نموذج طلب إقامة المزاد التنظيمي:**

   - **الأثر:** فشل توليد ملف PDF لطلب إقامة المزاد بسبب التفاف اسم المنشأة المكون من عدة كلمات وخروجه عن الحد الأقصى للارتفاع (20pt).
